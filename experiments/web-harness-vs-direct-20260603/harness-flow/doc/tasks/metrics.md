# 指标计算模块

## 模块目标

实现 `calculateMetrics`，基于完整任务列表计算 KPI：总任务数、完成百分比、总工作量、未完成高优先级任务数。

## 依赖输入

- `doc/proposal.md`
- `doc/detailed-design.md`
- 数据模型模块输出
- `src/app.js`

## 不做什么

- 不读取筛选条件。
- 不操作 DOM。
- 不读写 `localStorage`。

## 任务 checklist

- [x] 实现 `calculateMetrics(tasks)` named function，并确保可在非浏览器环境调用。
- [x] 计算总任务数为完整任务数组长度。
- [x] 计算完成百分比为 `done` 状态任务数量除以总任务数。
- [x] 当总任务数为 `0` 时，将完成百分比设为 `0`。
- [x] 将完成百分比四舍五入为整数百分比显示所需值。
- [x] 计算总工作量为所有任务 `effort` 求和。
- [x] 计算未完成高优先级任务数为 `priority === "high"` 且 `status !== "done"` 的任务数量。
- [x] 返回结构化 metrics 对象，供 `renderBoard` 更新 KPI 区。
- [x] 确保计算结果不受搜索、状态筛选或负责人筛选影响。

## 验收标准

- 空任务列表返回总数 `0`、完成 `0%`、工作量 `0`、未完成高优先级 `0`。
- 全部任务完成时完成百分比为 `100%`。
- 完成百分比按任务数量计算，不按工作量加权。
- 筛选条件改变时 KPI 仍反映完整任务列表。

## 测试要求

- [x] 验证空列表、部分完成、全部完成三种场景。
- [x] 验证高优先级 done 任务不计入未完成高优先级数量。
- [x] 验证工作量求和使用归一化后的数字。

## 验证记录

- `tests/test_app_logic.py` 覆盖空列表、部分完成、全部完成、高优先级 done 不计入未完成数量和工作量求和。
- Node-backed 逻辑断言通过，KPI 在 DOM smoke 中确认不受筛选条件影响。

## 风险和注意事项

- KPI 显示格式由渲染模块决定，计算模块应优先返回数值，避免字符串格式耦合。
- 不要把筛选后的可见任务误传给 `calculateMetrics`。
