# JSON 导入导出模块

## 模块目标

实现当前完整任务列表的 JSON 导出，以及任务数组或 `{ "tasks": [...] }` 对象格式的原子导入替换。

## 依赖输入

- `doc/proposal.md`
- `doc/detailed-design.md`
- 归一化模块输出
- 持久化模块输出
- 渲染模块输出
- 交互控制模块输出
- `src/app.js`

## 不做什么

- 不合并导入任务和当前任务。
- 不接受设计文档之外的导入格式。
- 不在导入失败时覆盖当前任务数据。

## 任务 checklist

- [x] 绑定 JSON 导出按钮事件。
- [x] 导出完整 `appState.tasks`，不导出当前筛选后的可见任务。
- [x] 使用 `JSON.stringify(tasks, null, 2)` 生成可读 JSON。
- [x] 使用 Blob 和临时下载链接触发本地 JSON 文件下载。
- [x] 导出后不改变当前任务状态、筛选条件或存储内容。
- [x] 绑定 JSON 导入控件或文件输入事件。
- [x] 读取导入文件文本并执行 `JSON.parse`。
- [x] 接受任务数组格式：`[{...}, {...}]`。
- [x] 接受包含 `tasks` 数组的对象格式：`{"tasks": [{...}, {...}]}`。
- [x] 对其他格式显示简洁错误反馈，并保持当前任务列表不变。
- [x] 对每条导入任务执行 `normalizeTask`，并过滤空标题任务。
- [x] 仅在解析、格式识别和归一化完成后替换 `appState.tasks`。
- [x] 导入成功后调用 `saveTasks`，重置失效负责人筛选，调用 `renderBoard`。
- [x] 导入空数组时视为合法导入，替换为无任务状态。
- [x] 导入失败后清理文件输入值，允许用户重新选择同一文件。

## 验收标准

- 导出 JSON 表示完整任务列表。
- 导入任务数组会替换当前任务列表。
- 导入 `{ "tasks": [...] }` 会替换当前任务列表。
- 非法 JSON、合法 JSON 但格式错误、`tasks` 非数组都不会覆盖当前数据。
- 成功导入后 KPI、看板、负责人筛选和 `localStorage` 同步更新。

## 测试要求

- [x] 人工验证导出文件内容包含完整任务列表。
- [x] 验证数组导入、对象导入、空数组导入。
- [x] 验证非法 JSON、无 `tasks` 数组对象和 `tasks` 非数组对象。
- [x] 验证导入失败后现有任务仍保留。

## 验证记录

- 内存 DOM smoke 覆盖导出完整任务列表、数组导入替换、对象导入替换、非法 JSON 不覆盖。
- Node-backed 逻辑断言覆盖 JSON 持久化路径；导入替换只在解析和归一化完成后更新 `appState.tasks`。

## 风险和注意事项

- 导入替换必须是原子性的，不能边解析边覆盖当前状态。
- 导出下载链接创建后应及时清理，避免 DOM 残留。
