# 交互控制模块

## 模块目标

实现 DOM 启动保护、应用状态初始化和事件绑定，让新增、搜索、筛选、状态变更、删除等核心交互按设计数据流运行。

## 依赖输入

- `doc/proposal.md`
- `doc/detailed-design.md`
- 页面结构模块输出
- 归一化、持久化、筛选、渲染模块输出
- `src/app.js`

## 不做什么

- 不实现 JSON 文件解析和 Blob 下载细节。
- 不新增后端或异步服务。
- 不弹出删除二次确认。

## 任务 checklist

- [x] 使用 `typeof document !== "undefined"` 保护 DOM 启动逻辑。
- [x] 在 DOM 可用后执行初始化，调用 `loadTasks()` 填充 `appState.tasks`。
- [x] 初始化 `appState.filters` 为 `query: ""`、`status: "All"`、`owner: "All"`。
- [x] 绑定任务表单提交事件。
- [x] 在表单提交时读取标题、负责人、工作量、优先级、状态和备注。
- [x] 标题为空或纯空白时显示简洁反馈，不新增任务。
- [x] 有效提交时调用 `normalizeTask`，追加到 `appState.tasks`，调用 `saveTasks`，再调用 `renderBoard`。
- [x] 新增成功后清理表单到可继续录入状态。
- [x] 绑定搜索输入事件，更新 `filters.query` 并重渲染，不写入 `localStorage`。
- [x] 绑定状态筛选事件，更新 `filters.status` 并重渲染。
- [x] 绑定负责人筛选事件，更新 `filters.owner` 并重渲染。
- [x] 使用事件委托处理卡片状态变更，按任务 id 更新 status、保存并重渲染。
- [x] 使用事件委托处理删除按钮，按任务 id 删除任务、保存并重渲染。
- [x] 删除任务时不弹二次确认。
- [x] 所有操作反馈写入统一反馈区域。

## 验收标准

- 模块在非浏览器环境加载不会失败。
- 新增有效任务后任务出现在对应状态列，KPI 和存储同步更新。
- 空标题提交不会新增任务。
- 搜索和筛选改变可见任务，但不写入存储。
- 卡片状态变更和删除能准确定位对应任务。

## 测试要求

- [x] 运行契约测试，确认 DOM 启动保护和 named functions 不冲突。
- [x] 人工 smoke test：添加任务、移动任务、删除任务、搜索任务、按状态筛选、按负责人筛选。
- [x] 验证每次任务变更后刷新页面仍能恢复数据。

## 验证记录

- `python3 -m unittest discover -s tests` 通过。
- 内存 DOM smoke 覆盖新增有效任务、空标题拒绝、状态变更、删除不确认、搜索、状态筛选、负责人筛选和重新导入模块模拟刷新恢复。

## 风险和注意事项

- 事件绑定只应初始化一次，避免多次 render 后重复触发。
- 任务状态更新后必须经过保存和重渲染，不能只改 DOM。
