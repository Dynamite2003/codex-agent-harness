# 样式和响应式模块

## 模块目标

实现安静、密集、实用的 dashboard 工具界面，并保证桌面和移动端下 KPI、表单、筛选器、看板列和任务卡片可读可操作。

## 依赖输入

- `doc/proposal.md`
- `doc/detailed-design.md`
- 页面结构模块输出
- 看板渲染模块输出
- `src/styles.css`

## 不做什么

- 不使用外部字体、图片、CDN、框架或装饰性渐变。
- 不制作营销页视觉。
- 不用 viewport width 直接缩放字体。

## 任务 checklist

- [x] 定义基础颜色、边框、间距和字体系统，以中性色为主体并使用有限状态色。
- [x] 实现 header、主区域、KPI、表单、工具区和看板的整体布局。
- [x] 在桌面端使用紧凑 dashboard 布局，避免过大的 hero 式排版。
- [x] 将 KPI 区设计为稳定网格，避免动态数值导致布局跳动。
- [x] 将任务表单和筛选工具区设计为易扫描、易操作的工作区。
- [x] 将四列看板设计为稳定网格，每列具备最小高度和明确边界。
- [x] 设计任务卡片样式，清晰展示标题、负责人、工作量、优先级、状态和备注。
- [x] 为不同优先级和状态提供文本可读的视觉区分，不只依赖颜色。
- [x] 为按钮、输入框、select、文件输入和卡片控件添加可见 focus 状态。
- [x] 实现移动端断点，使 KPI、表单、筛选器和看板列纵向堆叠。
- [x] 检查窄屏下长标题、长负责人、长备注和按钮文字不会重叠或溢出。
- [x] 确保 hover、focus 和动态内容不会改变固定格式控件的尺寸。

## 验收标准

- 桌面端页面密集、清晰、适合重复操作。
- 移动端文本不重叠，表单和卡片可操作。
- 看板列、卡片和控件尺寸稳定。
- UI 不依赖外部资源。
- 页面没有装饰性渐变、外部图片或 landing page 构图。

## 测试要求

- [x] 人工检查桌面视口下 KPI、表单、筛选器和四列看板。
- [x] 人工检查移动视口下字段、按钮、卡片和列标题不重叠。
- [x] 使用长标题、长负责人和长备注任务验证换行和溢出处理。
- [x] 验证键盘 focus 状态清晰可见。

备注：样式实现已按实际 HTML/JS 类名收敛；CSS 静态检查确认 `@media`、换行保护、稳定网格、focus 状态和禁止外部资源/渐变规则。真实桌面/移动浏览器视口复核受环境限制，详见 `doc/tasks/verification.md`。

## 风险和注意事项

- 颜色系统应服务状态识别，不要让页面变成单一色调。
- 样式不能隐藏契约测试要求的文本或元素。
