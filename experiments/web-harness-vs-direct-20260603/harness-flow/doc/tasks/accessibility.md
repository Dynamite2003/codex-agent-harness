# 可访问性模块

## 模块目标

保证 Sprint Board Lite 的表单、筛选器、任务卡片、状态变更、删除、导入导出和反馈区域具备基本键盘可用性和语义可理解性。

## 依赖输入

- `doc/proposal.md`
- `doc/detailed-design.md`
- 页面结构模块输出
- 交互控制模块输出
- 样式和响应式模块输出

## 不做什么

- 不引入额外可访问性库。
- 不改变已确认的产品规则。
- 不用颜色作为唯一信息表达方式。

## 任务 checklist

- [x] 检查所有表单控件都有显式 `label` 和正确 `for` 关联。
- [x] 检查搜索、状态筛选和负责人筛选具备可理解 label。
- [x] 检查导出按钮、导入控件、删除按钮和状态变更控件具备明确文本或上下文。
- [x] 为反馈区域添加 `aria-live="polite"`。
- [x] 确保空标题提交、导入成功和导入失败反馈会写入反馈区域。
- [x] 确保任务卡片展示优先级和状态文本，不只用颜色表达。
- [x] 确保键盘用户可以聚焦并操作表单、筛选器、状态控件、删除按钮和导入导出控件。
- [x] 确保 focus 状态在按钮、输入框、select 和文件输入上清晰可见。
- [x] 检查动态渲染任务卡片后，控件仍保持可访问名称。
- [x] 检查移动端控件点击目标和文本可读性。

## 验收标准

- 所有高频交互可通过键盘完成。
- 所有表单控件和筛选控件可被辅助技术理解。
- 操作反馈不会只通过视觉位置变化表达。
- 任务状态和优先级不只依赖颜色。

## 测试要求

- [x] 使用键盘完成新增、搜索、筛选、状态变更、删除、导出和选择导入文件。
- [x] 人工检查 label 与控件 id 的关联。
- [x] 人工检查反馈区域在表单错误和导入错误时更新。
- [x] 运行契约测试，确认可访问性调整未破坏必要结构。

## 验证记录

- 契约测试确认表单和筛选控件 `label for` 关联完整。
- `#feedback` 使用 `aria-live="polite"`；DOM smoke 确认空标题、导入成功和导入失败反馈写入该区域。
- 动态任务卡片包含优先级文本、状态文本、状态 select 的 `aria-label`/隐藏 label，以及带任务标题的删除按钮 `aria-label`。
- Focus 样式覆盖按钮、输入框、select、textarea 和文件输入；移动端点击目标和文本换行通过 CSS 静态检查。
- 真实浏览器键盘遍历未能执行：当前 in-app Browser 不可用，Playwright 包也不可用。原生控件与 focus 样式已按静态检查覆盖。

## 风险和注意事项

- 动态创建卡片时容易遗漏控件 label 或可访问名称，应在渲染函数中统一生成。
- focus 样式不能被全局 reset 或低对比度颜色覆盖。
